## Verdict

V6 is structurally sound. Published lessons are generated by `getStaticPaths()` from the validated `practice` collection; unpublished entries are filtered before route generation. The full static lesson remains available below the optional React island, so the page has a readable no-JavaScript and printable path. Keystatic is local-only and is injected only for development when `KEYSTATIC_LOCAL=1`; the production build workflow does not enable it.

No P0, P1, or P2 blocker was found. The parent evidence reports the CMS save/restore, draft exclusion, 18 regressions, route and SEO checks, and responsive/no-JavaScript QA as passing. One P3 follow-up remains: content validation checks the date shape but not whether `reviewedOn` is a real calendar date.

## Findings

### P3 — `reviewedOn` accepts impossible calendar dates

`src/content.config.ts` validates `reviewedOn` with only `/^\\d{4}-\\d{2}-\\d{2}$/`. Values such as `2026-99-99` satisfy the schema. This field is editor metadata and is not rendered publicly, so it is not a release or privacy defect. Add a calendar-date refinement if the field will drive review reports or release decisions.

## Evidence-backed strengths

- `src/pages/resources/[lesson].astro:6-8` filters the collection to `data.published` in `getStaticPaths()`, so drafts cannot receive public lesson pages.
- The lesson template renders the same validated data into the static sheet and passes the step data to `PracticeGuide` (`[lesson].astro:28-41`), avoiding separate authored text for the interactive and no-JavaScript paths.
- The static sheet includes explicit activity boundaries: suggested practice, adjustable length/language, not a test, and not a full course lesson (`[lesson].astro:24-27`).
- `PracticeGuide.tsx` is optional progressive enhancement: it starts hidden until mounted, keeps the full sheet below, uses native buttons and an `aria-live` progress status, and provides previous/next/restart controls without recording or saved progress.
- The guide moves focus to its `h2` after user navigation (`PracticeGuide.tsx`), giving keyboard users a clear state-change announcement target.
- `src/content.config.ts` constrains title, summary, introduction, audience, minutes, materials, step count/lengths, prompts, listener guidance, feedback example, publication flag and review date; a refinement requires step minutes to equal the lesson total.
- `keystatic.config.ts` matches the JSON content path and exposes the `published` checkbox with a clear local-save/release-check description. Editorial notes are required for source review but are not rendered by the lesson page.
- `astro.config.mjs` only wires Keystatic when `KEYSTATIC_LOCAL=1`, and the wrapped integration delegates to Keystatic only for `context.command === "dev"`. `scripts/start-cms.mjs` binds the local editor to `127.0.0.1`.
- `sitemap.xml.ts` dynamically adds published lesson IDs to the curated public routes. The static allowlist intentionally does not duplicate the lesson route; the content check verifies published listing/sitemap inclusion and draft exclusion.
- `scripts/check-practice-content.mjs` checks source parity, step totals, public listing, sitemap inclusion, editor-note absence across generated text assets, absent Keystatic/API build targets, draft non-emission, and no homepage hydration sentinel.
- The deployment workflow installs the locked pnpm dependencies, builds without enabling the local editor, and runs the practice-content check alongside route, SEO, schedule privacy, inquiry, and speech regressions.
