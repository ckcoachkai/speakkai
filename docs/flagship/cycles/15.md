# Version 15 — Smaller shared assets and release budgets

Status: release candidate. Entering champion V14: 43/55.

## Research before edits

Fresh 51Talk and Apple homepage research compared first-view hierarchy and image selection. Official web.dev and Astro documentation supports responsive local images, reserved dimensions, selective font declarations and static output. See v15-china.md and v15-global.md. Raw response sizes do not establish competitor quality or user outcomes.

Hypothesis: replace the oversized shared logo request and unnecessary font declarations while preserving the established identity, typography and layout; enforce repeatable byte guardrails before richer media.

## Implementation and objective comparison

Astro now creates 160/320/480px WebP logo candidates from a byte-identical copy of the original PNG. The original stays available. Existing desktop/mobile crop positioning is unchanged; the logo loads eagerly. Sharp 0.34.5 is an explicit locked build dependency after the first optimization build reported it missing. Manrope keeps the same 400/600/700 weights with Latin-only declarations and the existing Chinese system fallback.

Generated WebP dimensions and format were verified. Candidate sizes: 2,102 / 4,226 / 6,456 bytes, versus the original 760,917-byte PNG. A 1x desktop browser chose the 160px file; a 3x 320px viewport chose the 480px file. Shared CSS observed on Home fell from 44,197 to 23,524 bytes. Actual requested Latin WOFF2 remains 42,492 bytes. One uncached localhost desktop comparison saw resource body bytes fall from 968,842 to 189,354 excluding HTML/favicon. These are asset-byte results, not field speed measurements.

Added a CI budget checker for twelve routes, including recursive referenced CSS/JS, Astro islands, all srcset candidates and font fallbacks. It reports raw per-route bytes, deduplicated assets and full artifact size separately. See PERFORMANCE-BUDGETS.md and v15-budget.json for thresholds, exclusions and limitations. The initial 350 KB image guard exposed Resources at 350,803 bytes; the final 400 KB guard accommodates its existing thumbnails. Legacy assets and speech-tool files still contribute to the full artifact.

## Validation

49-page final build: zero errors/warnings, seven existing hints. Twelve route checks and 210 local targets, twelve JSON-LD graphs, eighteen sitemap entries, course/editorial checks, Chinese practice parity, twenty inquiry/Speak tests, schedule privacy, byte budgets and diff checks passed. The existing image checker was corrected to recognize Astro's valid bare alt attribute for decorative empty alt text.

All twelve routes at 320×900 and 1440×900 showed loaded logos, preserved 126/158px image widths, version 15 and no horizontal overflow. Desktop/mobile homepage and Chinese practice screenshots reviewed; no observed crop or typography regression. Density, cache and scripting emulations were restored. Source review found no release blocker, with explicit scanner limitations for runtime-generated requests and inline dependency discovery.

## Critique and champion comparison

Improved: the repeated large logo download is removed from flagship image markup, CSS declarations shrink, and future byte regressions have a release gate. Average: guided practice still pays for React, old public assets remain in the deployment, and real network/field measurements are absent. Ahead of a visual-only redesign: the same interface now serves a dramatically smaller identity asset. Behind a mature performance program: there are no field Core Web Vitals or real China-network samples yet.

Scores: 3.5, 2, 4.5, 4.5, 4, 4, 4.5, 4.25, 3.5, 4, 4.75 = 43.5/55. Performance increases by 0.5 for verified byte reductions and guardrails; other categories stay unchanged. Conversion, speed in the field and visitor trust remain unmeasured.

Other engines, screen readers and native full-site text enlargement remain unverified.
