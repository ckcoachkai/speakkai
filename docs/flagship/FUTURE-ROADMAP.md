# SpeakKai future improvement roadmap

Start from V30 and preserve its public routes, bilingual scope, schedule privacy and tools. This roadmap does not schedule work or install analytics.

| Priority | Concrete work | Acceptance evidence |
|---|---|---|
| Authentic teaching proof | Select a short real demonstration with public-use permission and exact attribution | Approved final clip, transcript, rights record, mobile playback and static alternative |
| Audience research | Observe parents, schools and companies choosing an offer, trying a practice and preparing an inquiry | Anonymous wrong turns, task completion and missing information; no assumed population conversion rate |
| Accessibility and devices | Test screen readers, Firefox/WebKit, actual text resize, Android/iOS and physical print | Named device/browser/assistive technology, reproducible issues and verified fixes |
| China-network delivery | Measure representative routes on real mobile networks | Repeated LCP/CLS/INP and actual transfer evidence with network context |
| Inquiry clarity | Check optional fields, copy/manual fallback and direct WeChat handoff | Visitors understand that a local draft is not sent or a booking |

## Sustainable content and measurement

Use local Keystatic for reviewed practices and paired course narrative; keep source-managed Chinese practice copy synchronized. Add activities based on real questions. New media should teach something the current examples do not.

Use CONVERSION-RECOMMENDATIONS.md to select one comparison. Define audience, primary outcome, guardrails and observation window before running it. Derive statistical sample sizes from real baseline rates and meaningful effects. Page views, playback and clipboard success do not establish trust, learning or bookings. Search-property and analytics integration need a product decision and privacy design; none was installed for this program.

## Architecture gates

V1–5 established Astro. V6–15 added isolated React and local Keystatic. V16–25 evaluated Next.js and retained Astro because no request-time requirement was unmet. V26–30 integrated actual Remotion, Blender and AI assets as optimized static media.

Reconsider when a named requirement needs protected accounts, durable bookings or remote editorial preview. Compare Astro plus a service, Astro server rendering, a hosted CMS and Next.js. Prove URL, language, CMS, privacy, tool and performance parity in an isolated prototype. A version number or framework preference is not a migration trigger. See ARCHITECTURE.md.

## Continue the improvement process

Research one hypothesis, build, run checks, inspect desktop/mobile and changed states, write a critique and five priorities, then compare with the champion. Publish fast-forward through GitHub Pages and verify the public version. Keep commit/workflow/rollback evidence in releases.json. Roll back with a reviewed revert/reconciliation; never overwrite unrelated newer work or force-push.

Scores are editorial guidance. Real visitor evidence can overrule internal preferences. Credentials, testimonials, affiliations and results require attributable publishable evidence; generated media and polished design cannot supply it.
